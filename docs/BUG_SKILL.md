# Bug 排查修复 Skill（根因优先）

## 1) 锁定现象

- 触发条件：
- 预期结果：
- 实际结果：
- 首次出现版本：

通过标准：可以稳定复现，且有最小复现路径。

## 2) 切分链路
把流程拆成 3 段逐段验证：
- 输入层（参数/状态/环境）
- 执行层（核心逻辑/子进程/通信）
- 输出层（返回值/UI/文件）

通过标准：明确第一个不符合预期的断点。

## 3) 定位根因
只回答三件事：
- 为什么开发环境正常而打包异常（或相反）
- 具体哪一行逻辑导致失败
- 为什么会在该条件下稳定触发

通过标准：根因可解释全部现象，而不是只解释一部分。

## 4) 最小修复
- 只改根因点，避免补丁式分支
- 复用现有链路，不引入重复实现
- 保证异常处理与资源释放闭环

通过标准：改动最小、可读、可维护。

## 5) 回归验证
先小后大：
- 最小场景回归（本问题）
- 相邻场景回归（同模块关键路径）
- 打包场景回归（若问题与打包相关）

通过标准：问题消失且无新增回归。

## 快速使用
每次查 Bug 按顺序执行：
1) 锁定现象
2) 切分链路
3) 定位根因
4) 最小修复
5) 回归验证
6) 用交付模板输出结论
